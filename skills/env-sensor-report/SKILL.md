# 환경 센서 데이터 → 분석 리포트

교실·실험실 등에서 모은 **환경 센서 CSV 하나**를 넣으면 **누구나 읽을 수 있는 분석 리포트**를 만든다.
열 이름이나 형식이 달라도 동작하도록, 계산은 스크립트가 하고 해석은 Claude가 쓴다.

## 설계 의도

이 리포트의 목적은 **"교실에서 언제 환기할지 정하는 것"**이다. 그래서 리포트 맨 위에 두 가지를 둔다.

1. **⚠️ 기준 초과 경고**: 한눈에 위험한 항목부터 보이도록 🔴 경고 / 🟠 주의 / 🟢 양호로 표시한다.
   - 🔴 경고: 측정 시간의 10% 이상이 기준을 벗어남
   - 🟠 주의: 기준을 벗어난 적이 있음(10% 미만), 또는 CO₂가 기준(1,000ppm)은 지켰지만 800ppm 이상인 시간이 10% 이상
   - 🟢 양호: 측정 기간 내내 기준 안
   - 기준보다 높아서 문제면 최고값을, 낮아서 문제면(온도·습도) 최저값을 함께 보여 준다.
2. **🪟 환기 시간 제안** (CO₂ 열이 있을 때):
   - **첫 환기 시각**: 날마다 CO₂가 800ppm 이상으로 **5분 넘게 이어지기 시작한 시각**의 중앙값. 그 전에 첫 환기를 하라고 안내한다.
   - **환기 간격**: 10분 구간마다 CO₂가 오르는 속도(분당 ppm)의 중앙값으로, 환기 직후 수준(하위 10% 값)에서 1,000ppm까지 걸리는 시간을 계산한다. 기준에 닿기 전에 환기하도록 **20% 여유를 두고 5분 단위로 내린 값**을 권장 간격으로 제시한다(최소 10분).
   - **신경 쓸 시간대**: 시간대 평균이 800ppm 이상인 시간.

## 이 스킬이 하는 일

0. 리포트 맨 위에 **⚠️ 기준 초과 경고**와 **🪟 환기 시간 제안**을 만든다 (위 "설계 의도" 참고).
1. CSV에서 **시간 열**과 **숫자 열**을 자동으로 찾는다 (구분자 `,` `;` 탭, UTF-8/BOM 모두 지원).
2. 열 이름으로 항목을 알아본다: CO₂ · 온도 · 습도 · 기압 · 가스(VOC) · PM2.5 · PM10 (한글 열 이름도 인식).
3. 항목별 **평균·중앙값·최소·최대·표준편차**, **시간대(0~23시)별 평균**, **측정 공백 구간**을 계산한다.
4. **학교보건법 시행규칙 교사 안 공기질 기준**과 비교해 기준을 벗어난 비율과 가장 길게 이어진 구간을 찾는다.
   - CO₂ 1,000ppm 이하 · 온도 18~28℃ · 습도 30~80% · PM10 75㎍/㎥ 이하 · PM2.5 35㎍/㎥ 이하
5. Claude가 결과를 읽고 **해석과 제언**(환기 시점, 수업 시간과의 관계, 센서 상태 등)을 써 넣는다.

## 진행 순서

### 1. CSV 확인
- 사용자가 경로를 주지 않았으면 현재 폴더에서 `*.csv`를 찾고, 여러 개면 어느 것인지 묻는다.
- 첫 몇 줄을 읽어 열 이름과 형식을 확인한다. 데이터가 원격(예: 라즈베리파이)에 있으면 먼저 복사해 온다.

### 2. 분석 스크립트 실행
이 스킬 폴더의 `scripts/analyze.py`를 실행한다 (파이썬 표준 라이브러리만 사용, 설치할 것 없음).

```bash
python3 <스킬폴더>/scripts/analyze.py <CSV경로> --title "<리포트 제목>"
```

- Windows에서는 `python3` 대신 `python` 또는 `py`를 쓴다.
- 결과는 CSV 옆 `report_<파일명>/` 폴더에 생긴다: `report.html`, `report.md`, `summary.json`
- **파이썬이 없으면**: 사용자에게 설치를 제안한다 (Windows: `winget install Python.Python.3.12`, macOS: `brew install python`). 설치를 원하지 않으면 데이터가 들어 있는 곳(예: 라즈베리파이)에서 실행하고 결과 폴더를 가져온다.
- 스크립트가 "숫자 열을 찾지 못했습니다"라고 하면 CSV 형식을 사용자와 확인한다 (머리글 줄 유무, 구분자 등).

### 3. 해석과 제언 쓰기
`summary.json`과 `report.md`를 읽고, 아래 내용을 **Markdown 파일**(예: 출력 폴더의 `insights.md`)로 쓴 뒤
같은 명령에 `--insights`를 붙여 다시 실행한다. 두 리포트(md·html)의 "해석과 제언" 칸에 함께 들어간다.

```bash
python3 <스킬폴더>/scripts/analyze.py <CSV경로> --title "<리포트 제목>" --insights <출력폴더>/insights.md
```

insights.md는 문단, `- ` 목록, `**굵게**`만 쓴다 (제목 `#`은 쓰지 않는다).

- **한 줄 요약**: 전체적으로 공기질이 어땠는지 (예: "CO₂가 수업 중 자주 기준을 넘어 환기가 필요함").
- **주요 발견 3~5개**: 숫자를 근거로. 예) "CO₂는 측정 시간의 23%가 1,000ppm 초과, 특히 10~12시 평균 1,240ppm".
- **시간대 패턴**: `hourly_mean`에서 높아지는 시간대와 낮아지는 시간대. 학교라면 등교·수업·점심·하교 시간과 연결해 설명한다.
- **실천 제언 2~3개**: 환기 시점·횟수, 난방·가습 등 교실에서 바로 할 수 있는 것.
  `summary.json`의 `ventilation`(첫 환기 시각, 권장 간격)을 **학교 시정표와 연결**해 쓴다.
  예) "권장 간격 45분 → 매 쉬는 시간마다 환기", "09:15쯤 800ppm → 1교시 시작 전 환기".
  사용자가 시정표를 알려 주면 그것을 쓰고, 모르면 일반적인 시정(1교시 09:00, 수업 45분·쉬는 시간 10분)이라고 밝히고 쓴다.
- **데이터 한계**: 측정 기간이 짧거나 끊긴 구간이 있으면 밝힌다. 센서별 특성도 짚는다.
  - BME688 가스 저항(kΩ)은 **절대 기준이 없는 상대값**이다. 값이 낮을수록 VOC가 많다는 뜻이고, 처음 켠 뒤 수 시간~하루는 안정화 중이라 낮게 나온다.
  - 같은 항목을 두 센서가 재면(예: `temp_c`와 `scd_temp_c`) 차이를 비교하고, CO₂ 센서의 온도는 자체 발열로 높게 나올 수 있음을 언급한다.

해석은 **교사·학생이 읽는다고 생각하고** 쉬운 말로, 과장 없이 쓴다. 숫자는 summary.json에 있는 값만 쓰고 지어내지 않는다.

### 4. 결과 알려 주기
- `report.html` 경로를 알려 주고 브라우저로 열어 보라고 안내한다 (외부 라이브러리 없이 그래프가 그려져 오프라인에서도 열린다).
- 한 줄 요약과 주요 발견을 대화창에도 짧게 보여 준다.

## 다른 CSV에 쓸 때

| 상황 | 동작 |
|---|---|
| 열 이름이 한글 (`일시, 온도, 습도, 이산화탄소`) | 그대로 인식 |
| 시간 형식이 `2026/10/26 13:00`, `2026.10.26 13:00`, 유닉스 시간 | 자동 인식 |
| 시간 열이 없음 | 통계와 기준 비교만 하고 시간대 분석은 생략 |
| 모르는 숫자 열 (`light_lux` 등) | 통계·그래프는 만들고 기준 비교는 생략 |
